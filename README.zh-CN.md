# Nivra

[English](README.md) · [隐私政策](https://hibrielle.github.io/nivra/privacy.html#chinese) · [源码](https://github.com/Hibrielle/nivra)

一个 Chrome 下载管理扩展：管理任务、按规则归档、查看下载报告，也能把种子交给你自己的下载器。原生 Manifest V3，数据保存在本机。

首发版本 **1.0.0** 已于 2026 年 10 月 20 日提交 Chrome 应用商店审核，通过后自动公开发布，目前尚未上架。[版本记录](CHANGELOG.md) · [能力与测试证据](PARITY.md)

## 安装与更新

1. 解压 `nivra-1.0.0.zip`，打开 `chrome://extensions`，开启「开发者模式」。
2. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的目录。需要 Chrome 127 或更新版本。
3. 固定扩展图标，下载一个 PDF，检查是否进入下载根目录下的 `文档/年-月/`。

源码开发可直接加载仓库目录，也可执行 `npm ci`、`npm run pack` 后加载 `dist/unpacked`。更新文件后，在扩展管理页点「重新加载」。扩展运行不需要 Node.js；开发、打包和可选 MCP 需要 Node.js 22+。

首次打开管理页可点击「开始设置」，空弹窗也有入口。引导先确认 Chrome 下载根目录与 Nivra 归档子目录，再选择整理方式：「按文件类型分类」可以独立开关，时间在「不按时间 / 按月份 / 按日期」中选择一项。类型和时间同时开启时，还可调整目录先后顺序。

| 选择                 | 保存位置示例（相对于归档子目录） |
| -------------------- | -------------------------------- |
| 只按类型             | `文档/报告.pdf`                  |
| 只按月份             | `2026-10/报告.pdf`               |
| 只按日期             | `2026-10-20/报告.pdf`            |
| 类型和月份，类型在前 | `文档/2026-10/报告.pdf`          |
| 类型和日期，时间在前 | `2026-10-20/文档/报告.pdf`       |

关闭类型分类并选择「不按时间」时，会暂停自动归档，文件直接放进 Chrome 默认下载文件夹。下方的目录示例按当前规则实时更新，切换时有短暂过渡；系统开启「减少动态效果」时不播放动画。

这些选择只调整现有默认分类的保存目录，自定义目录、规则顺序和各条规则的启停状态保持原样。不同分类已有不同日期方式时，可保留各自设置，只修改需要调整的项；未匹配任何规则的文件仍使用 Chrome 默认下载位置。关闭引导不会保存未确认的修改。最后一步可预览并下载一个真实的 `nivra-test.txt`。引导可以跳过，并从「设置 → 重新查看使用引导」再次进入。

## 语言

默认跟随 Chrome：中文环境显示简体中文，其他语言显示英文。在「设置 → 界面语言」可手动选择 English、简体中文或跟随浏览器。切换会同步刷新已打开的管理页、弹窗与报告页，不修改已有文件名、规则、备注和归档目录。新建默认规则使用当时的界面语言。

## 常用操作

| 想做什么                     | 入口                                        |
| ---------------------------- | ------------------------------------------- |
| 查看进度、暂停、继续、取消   | 工具栏弹窗，或「打开下载管理器」            |
| 复制链接、定位文件、重新下载 | 任务右侧「⋯」菜单                           |
| 分类、搜索、多选、备注       | 管理页左侧分类与任务详情                    |
| 调整保存位置与分类规则       | 「设置 → 保存位置与默认分类」及「归档规则」 |
| 回看速度与连接信息           | 「⋯ → 下载报告」，或管理页任务详情          |

默认接管浏览器下载界面，新下载会展开进度面板；管理页在前台时直接更新列表。工具栏弹窗无法打开时会复用独立窗口。这两项行为可分别在设置中关闭。弹窗固定为 440 × 580 px，列表内部滚动；顶部可切换深浅模式，选择同步到管理页和报告页。支持系统的「减少动态效果」。

弹窗和管理页的任务右侧使用同一套「⋯」菜单，包含复制、打开文件、定位、重试、下载报告及规则操作；可用状态随任务更新。文件删除在两处使用相同的确认弹窗，显示实际路径。管理页支持单击查看详情、双击或按 Enter 打开文件，以及批量操作。打开文件使用浏览器或系统的默认方式，首次使用时按需申请权限；取消授权不会打开文件。下载完成后可通知，点击通知进入对应任务详情。

「仅移除任务」放入插件回收站，可以还原；「删除本地文件」需要确认并删除对应磁盘文件，不能保证进入系统废纸篓；「清除浏览器记录」只清下载历史。三个操作独立。

详情中的备注点击「保存备注」后持久保存；同一任务刷新时会保留未保存的草稿和展开区域。移除正在使用的自定义筛选器后，列表恢复全部任务。重新启用扩展时，会核对先前未结束任务的实际下载状态。

## 自动归档与规则

默认覆盖 **15 类文件、343 种扩展名**，提供 **21 个可搜索模板**。普通网页下载也会执行规则；未知类型保持浏览器默认位置。只处理之后开始的下载，不搬动已有文件。

打开「归档规则」，选模板或新建规则。一个规则中的不同条件按 AND 组合，扩展名列表内部按 OR。默认首条匹配规则生效，可在设置中改为最后命中。保存前使用「测试规则」查看目标路径、命中条件和优先级；支持撤销最近一次规则变更。

新建规则时，先选文件类型或填写后缀，再填保存目录；勾选「按月建子目录」即可按月归档。旁边持续显示示例文件的目标路径。网站、关键词、正则、命名模板与同名处理按需展开；编辑已有高级规则时，相应区域自动展开，保存仍保留完整规则能力。

| 需求                   | 示例                                                                      |
| ---------------------- | ------------------------------------------------------------------------- |
| 发票 PDF 按月归档      | 扩展名 `pdf`，文件名包含 `发票`，目录 `票据/{year}-{month}`               |
| 来自某个网站的安装包   | 域名 `example.com`，扩展名 `apk, aab, apks`，目录 `安装包/Android`        |
| 从文件名提取项目编号   | 正则 `^project-(\d+)-.*\.pdf$`，完整路径 `项目/${filename:1}/${filename}` |
| 保留某些文件的默认位置 | 指定条件，动作选择「保留浏览器默认位置」                                  |

条件支持扩展名、域名、关键词、MIME、URL 和正则。路径可使用 `{filename}`、`{name}`、`{ext}`、`{host}`、`{year}`、`{month}`、`{day}`、`{num:3}`，以及 RegExp 捕获组、日期模板和常用 Chrono 变量。完整路径模板优先于「目录 + 文件名」，本次批量命名优先于全局规则。页面标题、链接文字等信息需要通过资源扫描或批量入口提供；普通下载不保证具有这些信息。

完整正则在独立工作线程中运行，单次计算最多 600 毫秒。超时或规则错误会保留默认下载位置，并说明原因。重名策略包括自动编号、浏览器询问和确认后的覆盖。可导入的配置示例见 [examples/android-invoice.json](examples/android-invoice.json)。

### 保存位置

在「设置 → 保存位置与默认分类」点击「选择下载根目录」，进入 Chrome 下载设置修改位置。它影响整个浏览器的下载。可再填写 Nivra 的归档子目录，例如 `资料/下载`，最终路径为：

```text
Chrome 下载根目录 / 资料/下载 / 文档/2026-10 / report.pdf
```

规则只指定下载根目录内的相对路径，不支持绝对路径或 `..`。暂停归档、未匹配或被排除的普通下载仍使用浏览器默认位置；显式批量命名继续生效。浏览器「下载前询问保存位置」及其他下载扩展可能改变最终保存位置。

重新加载扩展会保留已有规则和用户设置，不自动改写旧默认分类。需要补充分类时，在设置中预览并导入默认规则。

## 下载报告

新下载会在后台约每秒采样，关闭弹窗和管理页后仍会记录。报告包括速度曲线、观测均速、采样峰值、暂停时间，以及开始、暂停、恢复、中断、取消和完成事件。可悬停曲线或用方向键查看具体采样，并复制诊断摘要。

均速只计算实际采到的传输区间；不足半秒的区间显示「样本不足」。暂停和缺失区间单独标注，不补成零速。长任务会聚合曲线。后台异常退出可能丢失最近约 5 秒的未落盘采样，恢复后标记空档；浏览器关闭期间无法采样。旧下载或已清理的记录可能没有报告。

连接信息来自下载时的浏览器事件，包括原始/最终域名、观测到的重定向和 IPv4/IPv6 地址，不事后查询 DNS。IP 可能是 CDN 或代理端点，不代表源站。网络请求没有下载任务 ID，Nivra 使用完整链接指纹与开始/恢复时间关联；无法确定归属时显示「无法确认」，没有观测数据时显示「未获取」。报告不自动判断慢速原因。

报告存于本机 IndexedDB，不进入云端同步或 MCP。每份最多 400 个聚合采样点、100 个事件和 32 条连接；已结束报告保留 30 天、最多 200 份，并按 8 MiB 数据预算优先清理旧报告。清除对应历史或自动清理任务时会清理报告，移入插件回收站则保留。复制摘要包含文件名、域名、已观测 IP 与统计，不含链接参数或本地路径。

## 资源发现与批量下载

在「资源嗅探」选择网页，扫描链接、图片、CSS 背景、懒加载地址和音视频直链，也可开启所选标签页的后续网络捕获。按类型、关键词、大小等筛选后加入队列。

批量入口支持粘贴链接、文件导入和范围地址，例如 `file-[001:020].pdf`、`[a:z]`、`[1:20:2]`。队列支持总并发、每站并发、定时派发和失败重试；单批最多 1000 个链接，队列最多 3000 项。定时派发依赖浏览器运行，可能延迟约 1 分钟；续传由 Chrome 和服务器共同决定。

文件内容交给浏览器或系统默认应用打开，Nivra 不提供独立文件预览页或自动打开文件。需要查看保存位置时，使用任务旁的文件夹按钮。归档路径预览和下载报告仍在插件内展示。

不提供多线程加速、HLS/DASH 分片合并、DRM 处理或网页内存中的 Blob 导出。

## 外部下载器

在「设置 → 外部下载器」绑定 **qBittorrent、Transmission 或 aria2**，填写 Web UI/RPC 地址和凭据，测试后保存。当前支持一个绑定。

已完成的 `.torrent` 任务可通过「⋯ → 发送到下载器」提交实际种子文件。未获得本地文件访问权限时，需选择对应文件。成功表示下载器已接收任务；下载进度、文件选择、保存目录和做种由下载器管理。当前不提供磁力链接入口或远端进度同步。

凭据单独保存在本机，不进入报告、规则导出、云端备份或 MCP。qBittorrent 接入只为本扩展访问所绑定 API 的请求适配 Origin/Referer，无需关闭客户端 CSRF 防护。

## 配置导入、备份与 AI

支持导入 `nivra-rules` 配置包、RegExp 原生规则 JSON，以及 Chrono 常用规则表达式。导入先预览、去重并校验，支持撤销；不是 Chrono 全部设置与历史版本的兼容器。完成后动作支持不操作或显示文件夹；带自动打开文件或预览动作的配置会提示先修改后再导入。规则云端备份使用 `chrome.storage.sync`，只备份规则，读取后仍需预览导入；可在设置中删除云端备份，本机规则保持不变。

不装 MCP 也可以在「导入 / AI 配置」复制提示词，让 AI 生成 JSON，再回到插件预览应用。

可选本地 stdio MCP：

```sh
npm ci
npm run mcp:config
```

将输出配置加入支持 stdio MCP 的客户端。工具为 `nivra_guide`、`nivra_create_pack`、`nivra_validate`、`nivra_simulate`，只生成、校验和试跑调用方提供的规则，不读取个人浏览器或直接修改插件设置。旧名称的规则格式与 MCP 工具名不再提供别名。

## 权限与数据

下载、存储、页面脚本、右键菜单、定时任务及 HTTP(S) 访问权限用于上述功能；通知、系统应用打开和本地文件访问按需授权。没有产品遥测。

| 数据                 | 保存位置与范围                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------ |
| 规则、设置、任务记录 | 本机；最多 500 条已结束任务，记录中的来源 URL 去除账号密码、查询参数和片段                 |
| 待下载队列           | 为实际发起下载保留原始链接，完成或取消后移除                                               |
| 资源嗅探结果         | 用户选中的标签页；浏览器会话内保存，关闭标签页或手动清空后移除                             |
| 下载报告             | 本机 IndexedDB；只保留关联到任务的统计与连接信息                                           |
| 请求关联缓存         | 为识别新下载短暂观察 HTTP(S) 请求，内存中最多 256 项、30 秒过期；不存 Cookie、请求头或正文 |

自动归档和报告不记录无痕下载。文件状态来自浏览器，不持续扫描磁盘。

## 开发与验证

运行时为原生 JavaScript ES Modules，没有 UI 框架或运行时 CDN。`vendor/` 包含本地依赖与许可；依赖更新后运行 `npm run build:vendor`。图标原稿为 `icons/brand.svg`，使用 `npm run build:icons` 重建 PNG。

```sh
npm ci
npm test
npm run pack
```

浏览器检查需要 Playwright Chromium，或用 `CHROME_EXECUTABLE` 指向 Chrome for Testing：

```sh
CHROME_EXECUTABLE=/path/to/chrome EXTENSION_DIR=dist/unpacked npm run test:reports
```

| 检查范围                             | 命令                                                        |
| ------------------------------------ | ----------------------------------------------------------- |
| 规则、采样、留存与 MCP 单测          | `npm test`                                                  |
| 报告采集、IP 关联、后台恢复          | `npm run test:reports`                                      |
| 任务菜单、下载交互、状态动画         | `npm run test:popup-menu` / `test:workflow` / `test:states` |
| 备注、键盘操作、筛选删除与停用后恢复 | `npm run test:details`                                      |
| 统一菜单、简单规则编辑与首次引导     | `npm run test:usability`                                    |
| 规则导入、归档与分类                 | `npm run test:e2e` / `test:classification`                  |
| 资源发现与外部下载器                 | `npm run test:advanced` / `test:downloaders`                |

测试使用隔离 Chrome 配置、本地服务与临时文件，结果写入 `artifacts/`。高级测试会在一次性扩展副本中预授可选权限，音视频样例另需 `ffmpeg`；这不代表原生授权弹窗已自动验证。外部下载器测试需要自备测试客户端，临时 Docker 环境可使用 `tests/downloader-lab.py` 创建和清理。

`npm run pack` 生成 `dist/unpacked`、`nivra-1.0.0.zip` 和 `SHA256SUMS.txt`，安装包不含 MCP、测试或开发依赖。

公开版本从 `1.0.0` 开始，之后修复问题递增补丁号（如 `1.0.1`），新增兼容功能递增次版本号（如 `1.1.0`），不兼容变更递增主版本号。此前的 `0.x` 只用于内部开发验证。
